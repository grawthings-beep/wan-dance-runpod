# SCAIL-2 品質比較の使い方

更新後はまず `scail2-preflight-runpod.json` で動作確認します。約0.25MP・9フレーム・
2ステップで、実GPUの生成からタイルVAEとMP4保存までを確認する専用設定です。
画質評価用ではありません。成功後、`scail2-quality-runpod.json` を開きます。キャラ画像とダンス動画を入れ、
プロンプトに実際のキャラの特徴を追記して約5秒だけ生成します。
品質版のユーザーログではRTX 6000 Ada 48GBで1窓40ステップに約87分かかり、
旧版はその後のタイルVAEデコードで失敗しました。修正版のGPU完走・画質は未検証です。

## workflow

| ファイル | 用途 |
| --- | --- |
| `scail2-preflight-runpod.json` | 更新後の短い動作確認。9フレーム・2ステップ、画質評価不可 |
| `scail2-quality-runpod.json` | 基準の品質版。参照画像1枚、DPO強度1 |
| `scail2-quality-multiref-runpod.json` | 同じキャラの顔アップ・背面・衣装詳細を1枚追加する実験版 |
| `scail2-comfyui-infinity-runpod.json` | 元の高速版。6ステップ＋LightX2Vのまま |

品質版は既存のFP8モデルを使い、LightX2Vを外して40ステップ、CFG 5、shift 3、
UniPC/simpleにしています。公式推論の基本値を参考にした比較の出発点です。
SAT版の完全再現や、あなたの画像で検証済みの最適値ではありません。

## まず1枚で比較する

1. Load Imageに元キャラ、Load Videoにダンス動画を指定します。
2. `Describe YOUR character...` のプロンプトに、顔・目・髪型・髪色・服の形・
   模様・アクセサリー・背景を具体的に記入します。初期の一般的な文章は画像を
   自動解析した説明ではありません。
3. SAMの人物指定は初期値が `human` です。アニメ絵で検出しない場合は、
   `anime character` や画像中の人物の特徴に変えます。マスクプレビューで目的の
   キャラが青く覆われることを確認します。青が空、手足や髪が大きく欠ける場合は
   そのまま長尺を生成せず、指定や入力画像を見直します。
4. DPO LoRAの強度を **1と0** で比較します。seed、プロンプト、画像、動画の範囲、
   解像度はそろえます。DPOは手や目・口の細部向けで、別人化を必ず防ぐものではありません。

プロンプトは命令文だけでなく、完成映像の描写にします。例えば
`A woman with silver twin tails and violet eyes wears a navy jacket with gold trim...`
のように書きますが、この例の髪色や服装は自分のキャラの特徴に置き換えてください。
見えない背面の模様などは推測で追加しません。

## 追加参照を試す

単一参照で比較した後、multiref版を開きます。`EXTRA VIEW` に同じキャラ・同じ服装の
顔アップか背面画像を指定します。初期状態は主画像と同じ `reference.png` なので、
本当の追加画像に変更してください。別キャラや違う衣装は混ぜません。

2枚目はSAMで別途検出し、主画像と同じ青色の人物として対応付けます。主画像の
マスク背景は白、追加画像の背景は黒です。追加画像とマスクは同じ縦横比で縮小・余白追加し、
画面から切り落とさず主画像と同じサイズにそろえます。顔アップを全身に見せかけて
動かすのではなく、追加の参照情報として入力します。

この版は単一キャラ用です。SAMが複数人を検出した場合は面積順のobject 0を選びます。
プレビューで別の人物が選ばれていたらSAMの人物説明を絞ってください。

公式は複数参照で画質が下がる可能性を明記しています。単一参照と比較し、顔や衣装が
安定しても二重化、動作の弱まり、背景の乱れが増えていないか確認します。

## 長尺に進む

初期値は24fpsで121フレームです。約5秒で、81フレーム窓の継ぎ目も含みます。
長尺にする場合は **Load Videoのframe_load_capとInfinityのmax_framesを両方0** にします。
片方だけ変えるともう片方で止まります。最初から曲全体を処理せず20〜30秒で確認します。

解像度は主画像を約0.9MPにして縦横を32の倍数にした値です。Infinityの幅・高さは
接続値が優先されるため、widgetに見える512×896を実際の出力サイズと誤認しないでください。
速度版との比較ではリサイズ設定と実際の出力サイズもそろえます。

比較時には顔の輪郭・目、髪飾り、服の模様、体型、背面から正面に戻った際の顔、
手で顔を隠した後の復元、元動画との振付・タイミング、窓の継ぎ目を確認します。
生成時間とピークVRAMも記録して採用設定を決めます。

## 更新とモデル取得

タイルVAEはComfyUI標準ノード経由で、空間・時間方向の重なり幅を明示します。
万一デコードで失敗した場合、該当窓の計算済みlatentを出力先の
`SCAIL/recovery/` に `.latent` 形式で保存してからエラーを返します。
これは該当窓の救済用で、動画全体の自動再開機能ではありません。
SQLiteの保存先も `/workspace/ComfyUI/user/comfyui.db` へ明示するよう修正しています。

DPOは固定revisionの約1.23GBを追加取得し、SHA-256を検証します。モデル取得完了の
ログを確認してから実行してください。旧Podのモデルだけで `DOWNLOAD_MODELS=0` にすると、
DPO不足で停止します。更新後の初回は `DOWNLOAD_MODELS=1` にします。

同梱名のworkflowを編集していた場合、更新前の内容はworkflowディレクトリの隣にある
`workflow-backups/<日時>/` に保存されます。任意の別名で保存したworkflowは変更しません。
ブラウザで開いていた古いcanvasは更新されないため、新しいworkflowを開き直します。

## 根拠と検証の範囲

- [SCAIL-2公式](https://github.com/zai-org/SCAIL-2): 推論設定、DPO、複数参照の注意点。
- [固定版ComfyUI](https://github.com/Comfy-Org/ComfyUI/blob/ca3dbe206c2fea84f2af4371ca13e9f2bfeb82e5/comfy_extras/nodes_scail.py): 参照画像を1枚ずつ別latentへ変換する公式経路。
- [DPO配布](https://huggingface.co/Comfy-Org/SCAIL-2/blob/86e1d4f5062f9c518d2b4b66e7aa3cc5110b38ec/loras/wan2.1_SCAIL_2_DPO_lora_bf16.safetensors): 固定revisionとSHA-256。

CIはworkflowの配線・モデル対応、バックアップ、オフライン処理、実際のComfyUI上での
CPU import・参照画像とマスクの変換・conditioningまで確認します。14Bモデルによる
GPU生成や、元キャラの保持率はこの検査では確認できません。
